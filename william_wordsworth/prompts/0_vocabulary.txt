# Wordsworth *Prelude* Anki vocabulary — complete updated specification

This is the self-contained instruction file for continuing the work. It incorporates the full original specification, all six agreed amendments, the clarification that actual corpus senses are always included, and the user's rule for reporting suspected typos after the main work. These changes are integrated into the relevant rules below; there is no separate amendment list to reconcile.

Sections 1–12 and 20–22 govern CSV expansion. Sections 13–19 preserve the complete existing AnkiDroid architecture and all four card templates as a reference. Section 23 contains essential project progress and resource information. Section 24 records the efficient continuation workflow and the essential lessons from Book 2. A new conversation needs this file and the requested source CSV, not the original instruction attachment or the detailed conversations about previous books.

Work on the book the user requests. CSV expansion does not itself authorise changing the card templates.

## 1. Purpose

The source files are existing 5-field Anki CSV files for individual books of Wordsworth's *The Prelude*.

The task is to convert each source file into a semantically reviewed 9-field CSV containing **exactly five English examples per normal vocabulary entry**, and zero examples for every source row whose original example field is empty.

This is **not merely a mechanical column expansion**. The additional examples should be used to review and, where useful, improve:

- Word Class
- English Explanation
- Czech Translations
- the original English Example

Only **English Word** is an immutable identifier.

---

# 2. Base/source CSV format

The source CSV is:

1. **English Word**
2. **Word Class**
3. **Czech Translations**
4. **English Explanation**
5. **English Example**

Example:

```text
"commerce","noun","styk, kontakt","communication or intercourse with others","He sought intellectual commerce with other scholars."

```

Technical properties:

- headerless CSV
- exactly 5 fields per row
- UTF-8
- standard CSV quoting
- retain the original row order
- merge repeated, character-for-character identical English Word values into one output row, retaining the first occurrence’s position and the useful semantic content of all merged rows (see section 22)

## Important distinction between source rows

There are two kinds of records, determined **strictly and exclusively by whether source field 5 is empty**. Do not infer record type from headword length, wording, punctuation, or the source Word Class. Do not speculate that a row has been misclassified.

A long expression with a non-empty original example is a normal record for this workflow and receives exactly five examples. A single word with an empty original example is an empty-example record and receives zero examples.

### A. Normal vocabulary records

Field 5, `English Example`, is non-empty.

These records must be expanded to **exactly five non-empty examples**.

### B. Phrase / quotation / example records

Field 5 is empty.

Treat these rows as empty-example contextual records. Their wording, length, or apparent lexical type never overrides the empty original example field.

**They must NOT receive generated examples.**

For such a row, all five target example fields must remain empty.

# 3. Definitive target CSV format

The new target files use this exact 9-field order:

1. **English Word**
2. **English Example**
3. **English Example 2**
4. **English Example 3**
5. **English Example 4**
6. **English Example 5**
7. **Word Class**
8. **English Explanation**
9. **Czech Translations**

Thus:

```text
English Word

English Example 2
English Example 3
English Example 4
English Example 5
Word Class
English Explanation
Czech Translations

```

The reason for this order is deliberate: first establish the actual usages of the word through the examples, then determine the relevant grammatical class or classes, formulate the English explanation of those senses, and finally formulate the Czech translations from that semantic context.

Target filename:

```text
wordsworth_prelude_bookN_anki_5examples.csv

```

No additional suffix such as `_revised`, `_download`, etc.

# 4. Immutable and editable fields

## English Word — absolutely immutable

Field 1 is the Anki matching key.

It must remain **character-for-character identical to the source CSV**.

Do not:

- modernize spelling
- change capitalization
- change singular/plural
- replace an inflected form by a lemma
- normalize an archaic spelling
- alter a phrase
- fix a suspected transcription error

Examples such as:

```text
befel
burthen
Tither
Wantoned

```

must stay exactly as supplied if they occur in `English Word`.

This preserves the existing matching value for Anki imports. During the initial expansion, do not change an identifier to resolve a spelling issue. Report suspected typos after completing the main work and let the user decide what to do, as specified in section 21. After the user explicitly requests particular corrections, those exact identifier changes are authorised: apply them to the existing expanded file, update any now-obsolete explanation, and preserve all unrelated content. Previous approvals are specific to the named changes and do not authorise correcting new books automatically.

## All other fields are editable

Fields 2–9 should be constructed according to semantic quality.

In particular, it is **wrong** to preserve Word Class, Explanation, Czech Translation, or original Example merely because they occur in the old CSV.

They may remain unchanged if already good, but they should be revised if the expanded examples expose:

- an incomplete definition
- a missing important sense
- an inaccurate Czech translation
- an incorrect word class
- a misleading explanation
- an awkward example
- a distinction between senses that the old record failed to express

# 5. Semantic workflow for a normal vocabulary record

For every source row with a non-empty original example:

### Step 1 — preserve English Word

Copy field 1 exactly.

### Step 2 — determine the relevant lexical senses

Start with the sense relevant to Wordsworth/source context. Use the 1805 text when checking the surrounding passage. **Always include an actual corpus sense, even if it is archaic, rare, unusual, bizarre, or marginal.** The exclusion of marginal usages applies only to additional senses outside the corpus usage.

Where identifiable, the source sense should appear in **Example 1** and as the first segment of Word Class, English Explanation, and Czech Translations. Do not guess confidently when the source sense or a suspected transcription is uncertain; handle uncertainty according to section 21.

Then include **all reasonably useful additional lexical senses and grammatical uses**. Do not impose a one-, two-, three-, or five-sense limit. Exclude bizarre or extremely marginal additional usages, but do not omit an ordinary useful meaning merely because it differs from the corpus sense. Do not mechanically copy every dictionary definition or split minor contextual shades into separate senses.

Normally, every included sense must be represented by at least one of the five examples. If there are **more than five distinct useful senses**, retain the additional senses in the aligned Word Class, English Explanation, and Czech Translations even when there is no example available for each of them. The example count remains exactly five. Every example must still demonstrate a sense included in the semantic fields.

### Step 3 — construct five useful examples

The original example can remain as Example 1 if it is good and demonstrates the source sense. Improve or replace it when necessary, including when it demonstrates a different sense from the corpus usage.

Construct exactly five genuinely independent, natural sentences. Distribute them across the useful senses, prioritising the corpus sense in Example 1 where identifiable. If more than five useful senses are retained, choose representative examples without dropping the unillustrated additional senses from the semantic fields.

### Step 4 — establish Word Class

Word Class must correspond to all retained senses and grammatical uses, including any useful senses beyond the five-example capacity. Use the lexical class, without tense information: for example, `verb`, not `verb, past tense`.

Put any helpful identification of tense, inflection, lemma, or historical spelling in English Explanation. Repeated classes such as `noun; noun` remain necessary when they represent different senses.

### Step 5 — write English Explanation

The explanation must describe the retained senses demonstrated by the examples, plus any additional useful senses retained under the more-than-five-senses exception. Do not define an example’s sense incorrectly or leave it unaccounted for.

### Step 6 — write Czech Translations

Translate all those established senses into Czech in the same order, including any useful senses beyond the five-example capacity.

For ordinary verb vocabulary, normally use Czech infinitives. For full expressions, preserve the actual grammatical form and meaning in translation. Relevant inflection information belongs in English Explanation, not in Word Class.

The Czech field therefore comes conceptually **after** the English explanation.

# 6. Multiple meanings and multiple word classes

Use the semicolon `;` as a strict **sense separator**.

The following three fields are positionally aligned:

- Word Class
- English Explanation
- Czech Translations

Each semicolon-delimited segment represents one distinct lexical sense/use.

## Example: different word classes

```text
English Word:
figure

Word Class:
noun; verb

English Explanation:
a person, shape, or representation; to decorate something with a pattern or design

Czech Translations:
postava, figura, vyobrazení; zdobit vzorem, vzorovat

```

Segment 1 corresponds across all three fields.

Segment 2 corresponds across all three fields.

## Example: different meanings with the same word class

```text
English Word:
commerce

Word Class:
noun; noun

English Explanation:
trade or exchange of goods; communication, intercourse, or intellectual exchange between people

Czech Translations:
obchod; styk, kontakt, duchovní výměna

```

Repeating `noun; noun` is intentional.

It preserves exact positional correspondence.

## Separator rules

Use:

```text
,

```

for alternatives or closely related formulations **inside one sense**.

Use:

```text
;

```

only to separate **independent senses/usages**.

Therefore:

```text
pozůstatek, zbytek, stopa

```

is one sense.

But:

```text
obchod; styk, kontakt

```

represents two senses.

### Strict alignment rule

If Word Class has 3 semicolon-separated segments, English Explanation and Czech Translations should also have 3 corresponding segments.

For example:

```text
noun; noun; verb
sense 1; sense 2; sense 3
translation 1; translation 2; translation 3

```

Do not use semicolons merely as stylistic punctuation inside one definition.

---

# 7. When NOT to split senses

Do not create separate semicolon segments merely because the five examples use the word in somewhat different circumstances.

Closely related shades of one lexical meaning remain one sense.

For example, if all five uses of `vestige` mean approximately:

> a small surviving trace or remainder of something

then one definition and one Czech segment are sufficient even if the examples concern:

- a ruined wall
- an accent
- an ancient custom
- hesitation
- a vanished settlement

A new semicolon segment is justified when there is a real lexical distinction comparable to a separate dictionary sense.

---

# 8. Example-generation quality requirements

This is critical.

The purpose of five examples is to expose **different real uses of the word**, not to manufacture five superficially different sentences.

## NEVER create variants like this

```text
His precipitate decision caused problems.
At the time, his precipitate decision caused problems.
In practice, his precipitate decision caused problems.
Years later, his precipitate decision caused problems.
Even then, his precipitate decision caused problems.

```

These are effectively one example repeated five times.

Do not generate diversity merely by adding generic wrappers such as:

```text
At the time,
In practice,
Years later,
In another context,
Even so,
In the scene,
Later,
In this case,

```

This failure occurred in earlier Book IX/X expansions and must not be repeated.

## Genuine variability

Examples 1–5 should differ where possible in:

- situation
- collocation
- grammatical construction
- syntactic environment
- register
- subject/object type
- literal versus extended use
- or distinct lexical sense

For a word with several relevant meanings, distribute the examples across those meanings.

For a word with only one relevant meaning, demonstrate different natural environments for that same meaning.

### Good example of one sense with varied contexts

For `dwindle`:

```text
Their supplies began to dwindle.
Attendance dwindled as the weather worsened.
His savings quickly dwindled after he lost his job.
The stream dwindles to a trickle in late summer.
Their hopes dwindled with each passing day.

```

These all belong to the same broad sense, but demonstrate different natural objects and constructions.

### Good example of multiple senses

If a word genuinely has two useful senses, the five examples should make both senses visible.

Every sense included in Word Class, English Explanation, and Czech Translations must normally be represented by at least one example. If more than five genuinely useful senses exist, additional senses may remain unillustrated, but must still have positionally aligned segments in all three fields. Exactly five examples are still required.

Conversely, **every example, without exception, must demonstrate a sense included in the explanation and Czech translation**. Do not force extra sentences into one example field simply to evade the five-example limit.

---

# 9. Example-writing style

Examples should be:

- natural standalone English sentences
- concise enough for Anki
- semantically transparent
- sufficiently varied
- grammatically complete where appropriate
- free of unnecessary literary interpretation
- free of generic framing added merely to manufacture difference

Inflection is allowed naturally.

For example, an entry `glean` can contain:

```text
She gleaned useful information from casual conversations.
Historians can glean much from household accounts.

```

The headword does not have to appear in exactly the same morphological form in all five examples.

Prefer normal idiomatic English rather than sentences artificially constructed only to contain the vocabulary word. Historical constructions may require appropriately literary examples, but the sentences must remain intelligible and useful.

Every entry must stand alone. Separate vocabulary entries must not rely on a longer-expression entry or say only “as in the phrase above.” If a long expression qualifies for five examples because its original example field is non-empty, apply the same genuine-variation standard to it; do not substitute five metalinguistic comments or superficial wrappers for real usage examples.

---

# 10. Special phrase / quotation records

If the original source field 5 (`English Example`) is empty, the entry belongs to the empty-example workflow, regardless of what the English Word field looks like. Use the original example field alone for classification.

For such rows:

```text
English Example   = ""
English Example 2 = ""
English Example 3 = ""
English Example 4 = ""
English Example 5 = ""

```

Do not invent examples.

The expression in `English Word` is already the material being studied.

Its:

- Word Class
- English Explanation
- Czech Translations

may still be corrected or improved if useful.

For longer expressions, the explanation should remain linguistic:

- syntax
- idiom
- archaic usage
- unusual lexical sense
- translation nuance

Do not introduce unnecessary literary interpretation.

# 11. Validation requirements

Before delivering each expanded CSV, verify:

### Structural validation

- same number of rows as source, except for required duplicate merges or additions/deletions explicitly requested by the user
- same original row order, retaining the first occurrence’s position for a merged duplicate
- exactly 9 fields per output row
- no header
- UTF-8
- valid CSV quoting
- no repeated English Word values in the delivered file
- exact required output filename, with no extra suffix
- document the counts of input rows, output rows, duplicate merges, normal records, and empty-example records

### Identity validation

For every retained source identifier:

```text
target English Word == source English Word
```

exactly. For a merged duplicate, the common identifier remains unchanged. No suspected typo permits an identifier change, deleted row, or additional corrected row without the user's subsequent instruction.

### Blank-record validation

For every source row whose original Example field is empty:

```text
target fields 2–6 are all empty

```

### Normal-vocabulary validation

For every source row with an original example:

- all five target example fields are non-empty
- examples are genuinely distinct
- no generic prefix/wrapper variants
- each listed sense appears in an example unless the row retains more than five useful senses, in which case unillustrated additional senses are allowed
- every example demonstrates a listed sense
- Example 1 and the first semantic segment reflect the source sense where identifiable
- no actual corpus sense has been excluded merely because it is rare or marginal
- no tense information appears in Word Class
- Word Class / Explanation / Czech segments correspond positionally
- Czech translations reflect all retained English senses, including any additional senses beyond the five-example capacity

### Semantic separator validation

Where semicolons are used, verify that the number and ordering of sense segments agree across:

```text
Word Class
English Explanation
Czech Translations

```

# 13. Current AnkiDroid TTS architecture

There are two cards.

## Card 1 — English → Czech

Front:

1. selected English example
2. English Word
3. Word Class
4. automatically speak selected example
5. then automatically speak English Word

Back:

1. same selected example
2. English Word
3. Word Class
4. Czech Translation
5. English Explanation
6. replay controls remain available

Do **not** use `{{FrontSide}}` on Card 1 back because it would rerender the randomized front.

The same example is independently reconstructed on front and back using deterministic selection from:

```text
card ID + repetition count

```

## Card 2 — Czech → English

Front:

1. Czech Translations
2. Word Class

Back:

1. `{{FrontSide}}`
2. selected English example
3. English Word
4. Word Class
5. English Explanation
6. automatically speak selected example
7. then automatically speak English Word

Using `{{FrontSide}}` here is safe because Card 2 front contains no randomized example or automatic English TTS.

# 14. Important AnkiDroid technical rules

Native Anki autoplay must be disabled.

If all five `{{tts ...}}` fields are present and native autoplay is enabled, Anki queues all five audio items before JavaScript hides four of them.

The templates instead click the native Anki replay buttons through JavaScript.

Use:

```javascript
".replaybutton, .replay-button, .soundLink"

```

Do not use browser:

```javascript
window.speechSynthesis

```

It did not work reliably in AnkiDroid.

Do not reintroduce:

- `sessionStorage`
- `localStorage`
- front/back timing markers

They were unnecessary and unreliable.

# 15. Current AnkiDroid JavaScript API

Use API version:

```javascript
const api = AnkiDroidJS.init({
    version: "0.0.3",
    developer: "local-template"
});

```

Methods are asynchronous and return wrapper objects.

Correct:

```javascript
const cardIdResult = await api.ankiGetCardId();
const repsResult = await api.ankiGetCardReps();

const cardId = cardIdResult.value;
const reps = repsResult.value;

```

Do NOT hash the wrapper objects themselves.

Selection seed:

```javascript
const seed =
    String(cardId) + ":" + String(reps);

```

Hash:

```javascript
function hashString(str) {
    let hash = 2166136261;

    for (let i = 0; i < str.length; i++) {
        hash ^= str.charCodeAt(i);
        hash = Math.imul(hash, 16777619);
    }

    return hash >>> 0;
}

```

Selection:

```javascript
const index =
    hashString(seed) % options.length;

```

Thus the same card/repetition gets the same example on front and back.

A later review gets a new seed.

Adjacent reviews may naturally select the same example because modulo selection is not designed to forbid repeats.

This currently works reasonably and should not be replaced with a more complicated mechanism unless specifically requested.

# 20. Critical migration summary

When converting an old Book CSV to the new format, do **not** treat the old semantic fields as authoritative.

The correct conceptual workflow is:

```text
immutable English Word
        ↓
identify useful lexical senses
        ↓
create/review five genuinely varied examples
        ↓
derive aligned Word Class
        ↓
derive English Explanation
        ↓
derive Czech Translations

```

The old data is a starting point, not something to preserve mechanically.

The only absolutely invariant value is:

```text
English Word

```

The empty-example rule is:

```text
old Example empty
→ this is already an example/quotation record
→ generate no additional examples
→ all five target example fields remain empty

```

The main quality failure to avoid is **pseudo-variation**: never manufacture four “new” examples by merely adding generic introductory phrases to the original sentence.

Preserve the actual corpus meaning even when rare. Include all reasonably useful additional meanings, with no arbitrary cap. If more than five useful senses exist, keep their aligned class, explanation, and Czech segments even when some lack examples. Merge exact duplicate identifiers as described below. Complete the main work before reporting suspected typos for the user's decision.
